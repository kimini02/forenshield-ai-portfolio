# 포렌식 사건 분석 UX 정책

이 문서는 딥페이크 포렌식 서비스에서 사건, 증거, 분석, 보고서, 삭제 흐름을 프론트엔드 화면 기준으로 정리한 UX 정책입니다.

핵심 목표는 사용자가 "사건을 분석한다"는 흐름을 이해하기 쉽게 만들면서, 백엔드의 포렌식/CoC 보존 정책과 충돌하지 않게 하는 것입니다.

## 1. 기본 도메인 기준

```text
사건
  여러 증거 파일을 묶는 단위

증거
  사용자가 업로드한 원본 파일 하나

분석 요청
  특정 증거 파일에 대한 AI 분석 작업

분석용 복사본
  원본 증거를 보호하기 위해 분석 과정에서 사용하는 임시 사본

보고서
  분석 완료 후 생성되는 PDF 제출/검토 자료
```

사용자가 말하는 "사건 분석"은 내부적으로는 다음 의미입니다.

```text
사건에 속한 여러 증거 파일을 각각 AI 분석 요청으로 등록한다.
```

따라서 프론트 화면은 사건과 증거를 구분해서 보여줘야 합니다.

## 2. 추천 화면 구조

### 2.1 메인 분석 화면

메인 화면은 "사건 분석 작업대"로 둡니다.

사용자는 두 가지 흐름을 선택할 수 있어야 합니다.

```text
새 사건
기존 사건
```

새 사건 흐름:

```text
1. 사건명 입력
2. 증거 파일 여러 개 업로드
3. 업로드된 증거 목록 확인
4. 분석 시작
5. 분석 요청 완료 후 새 사건 시작 가능
```

기존 사건 흐름:

```text
1. 기존 사건 선택
2. 기존 사건에 증거 파일 추가 업로드
3. 미분석 증거 또는 새 증거 선택
4. 분석 시작
```

## 3. 사건명 정책

사건명은 업로드 전에 필수로 받는 것이 좋습니다.

이유:

```text
증거가 처음 저장될 때부터 사건 기준이 생김
마이페이지 사건 목록이 안정적으로 구성됨
/cases/{caseId}와 /evidences/{evidenceId}가 섞이지 않음
CoC 로그와 감사 이력이 사건 맥락을 잃지 않음
```

권장 UX:

```text
사건명이 비어 있으면 파일 업로드 버튼 비활성화
또는 업로드 시 "사건명을 입력해 주세요" 에러 표시
```

## 4. 여러 파일 업로드 정책

한 사건에는 여러 증거 파일을 업로드할 수 있어야 합니다.

예:

```text
사건: 장도치-금연-사건
증거 1: video.mp4
증거 2: capture.png
증거 3: audio.wav
```

분석 요청은 증거 단위로 생성됩니다.

```text
Evidence 1 -> AnalysisRequest 1
Evidence 2 -> AnalysisRequest 2
Evidence 3 -> AnalysisRequest 3
```

프론트에서는 사건 안의 증거 목록을 보여주고, 전체 분석 또는 선택 분석을 지원할 수 있습니다.

## 5. 초기화 버튼 정책

`초기화`라는 이름은 의미가 모호하므로 `새 사건 시작`으로 바꾸는 것을 권장합니다.

`새 사건 시작`의 의미:

```text
현재 프론트 작업 화면만 비운다.
서버에 저장된 증거, 분석 요청, CoC 로그, 보고서는 삭제하지 않는다.
```

삭제와 초기화는 분리해야 합니다.

```text
새 사건 시작
  프론트 로컬 상태 초기화

업로드 취소
  아직 분석 전인 증거를 삭제 요청

분석 중단
  진행 중인 분석 요청 중단

원본 증거 삭제 요청
  원본 증거 soft delete
```

## 6. 마이페이지 / 사건 상세 / 증거 상세

권장 라우트:

```text
/cases/{caseId}
  사건 상세 페이지
  사건 정보와 증거 목록 표시

/evidences/{evidenceId}
  증거 상세 페이지
  해시, 메타데이터, 분석 결과, CoC 로그, 보고서 표시
```

마이페이지 사건 목록 클릭:

```text
/cases/{caseId}
```

사건 상세에서 증거 클릭:

```text
/evidences/{evidenceId}
```

## 7. 분석 상태 정책

업로드 완료와 분석 완료는 다릅니다.

```text
업로드 완료
  Evidence가 저장된 상태

분석 요청 완료
  AnalysisRequest가 QUEUED로 생성된 상태

분석 중
  AnalysisRequest가 ANALYZING인 상태

분석 완료
  AnalysisRequest가 COMPLETED인 상태
```

프론트 표시:

```text
QUEUED -> 대기
ANALYZING -> 분석 중
COMPLETED -> 분석 완료
FAILED -> 분석 실패
```

사건 목록의 상태는 사건 안의 증거 상태를 종합한 값입니다.

예:

```text
증거 A: COMPLETED
증거 B: PENDING

사건 상태: 대기
```

하나라도 대기/진행 중인 증거가 있으면 사건 전체가 완료로 보이지 않을 수 있습니다.

## 8. 원본 증거 삭제 정책

원본 증거는 바로 물리 삭제하지 않는 것이 좋습니다.

권장:

```text
soft delete
목록에서는 숨김
감사/관리 화면에서는 삭제됨 상태로 조회 가능
CoC 로그와 분석 결과/보고서는 보존
```

삭제 가능 조건:

```text
분석 중 또는 대기 중이면 삭제 불가
COMPLETED, FAILED, 미분석 상태면 삭제 요청 가능
```

삭제 모달 문구 예시:

```text
원본 증거 삭제 요청

이 작업은 증거를 목록에서 숨기고 삭제 상태로 표시합니다.
분석 결과, 보고서, 감사 로그는 보존됩니다.
진행 중인 분석이 있으면 삭제할 수 없습니다.
```

## 9. 분석용 복사본 정책

분석용 복사본은 사용자 액션으로 삭제하지 않습니다.

권장 흐름:

```text
분석 시작 전 원본에서 분석용 복사본 생성
복사본 해시 검증
AI 분석 수행
분석 완료 후 복사본 자동 삭제
CoC에 ANALYSIS_COPY_DELETED 기록
```

프론트에서는 복사본 삭제 버튼을 만들지 않습니다.

증거 상세에서 읽기 전용으로만 표시할 수 있습니다.

```text
분석용 복사본 상태: 삭제 완료
삭제 시각: ...
복사본 해시: ...
```

## 10. PDF 보고서 정책

PDF 다운로드는 한 번만 제한하지 않는 것을 권장합니다.

권장:

```text
보고서 생성은 한 번
PDF 다운로드는 여러 번 가능
다운로드할 때마다 REPORT_DOWNLOADED CoC 로그 저장
```

이유:

```text
수사관과 법무 담당자가 제출/검토 과정에서 반복 다운로드할 수 있음
다운로드 제한보다 다운로드 이력 추적이 포렌식 도메인에 더 적합함
```

UI 흐름:

```text
분석 완료 전
  보고서 생성/다운로드 비활성화

분석 완료 후 보고서 없음
  PDF 보고서 생성 버튼 표시

보고서 생성 완료
  PDF 다운로드 버튼 표시
  보고서 생성일, 생성자, reportHash 표시
```

## 11. 백엔드에서 당장 안 해도 되는 것

프론트 UX 정리 단계에서 백엔드가 당장 하지 않아도 되는 작업:

```text
Cases 테이블 새로 만들기
사건 자체를 분석하는 별도 AnalysisRequest 구조 만들기
PDF 1회 다운로드 제한 구현
분석용 복사본 삭제 버튼 API 만들기
원본 증거 물리 삭제 구현
분석 완료 후 메인 화면 세션 자동 삭제 API 만들기
초기화 API 만들기
```

이유:

```text
현재 구조는 Evidence.caseName/caseNumber 기준으로 사건을 묶고 있음
분석 요청은 Evidence 단위로 생성하는 것이 자연스러움
초기화/새 사건 시작은 프론트 로컬 상태 문제임
복사본 삭제는 시스템 내부 자동 처리 영역임
PDF 다운로드 제한은 도메인상 비추천임
```

## 12. 백엔드에서 필요한 것

프론트 UX를 안정화하려면 백엔드에는 아래가 필요합니다.

```text
파일 업로드 시 caseName 필수 검증
마이페이지 caseId가 evidenceId로 내려가지 않도록 유지
/api/v1/cases?caseKey=... 사건 상세 조회 안정화
사건 상세 응답에 evidences[].evidenceId 포함
증거 상세 응답에서 moduleResults, cocLogs는 null 대신 []
분석 상태 조회는 PENDING, PROCESSING, COMPLETED, FAILED 유지
원본 증거 삭제는 soft delete 정책으로 별도 설계
분석 완료 후 PDF 보고서 생성/다운로드 API 추가
REPORT_CREATED, REPORT_DOWNLOADED CoC 로그 저장
```

```text
메인

  사건명 필수
  여러 증거 업로드
  이 사건 분석 시작
  새 사건 시작

마이페이지
  사건 목록
  사건 상태
  사건 상세 이동

  사건 정보
  증거 목록
  증거 추가
  증거별 상세 이동
  사건 삭제 요청

증거 상세
  원본 해시
  메타데이터
  분석 결과
  CoC 로그
  PDF 보고서 생성/다운로드

```
