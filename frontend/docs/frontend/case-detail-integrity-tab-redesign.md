# 사건 상세 위변조·무결성 검증 탭 정리안

## 목표

위변조·무결성 검증 탭은 사용자가 한눈에 “원본이 바뀌었는지”, “해시와 서명이 맞는지”, “블록체인 기록이 있는지”를 판단하게 한다.

기준 화면 흐름:

1. 상단 3개 요약 카드
   - 위변조 의심 수준
   - 해시 검증 결과
   - 전자서명 상태
2. 위변조 의심 프레임 영역
   - 제목은 `위변조 의심 프레임 (주요 구간)`으로 둔다.
   - 카드형 썸네일 4개를 한 줄로 배치한다.
   - 각 카드에는 시각, 상태 배지(정상/주의), 구간 제목, 설명을 표시한다.
   - 프레임 막대 차트와 썸네일 목록을 동시에 두지 않는다. 현재 화면은 썸네일형 주요 구간 UI를 기준으로 한다.
   - 실제 프레임 이미지가 없으면 화면용 미리보기 배경만 사용하고, 실제 분석 점수를 새로 지어내지 않는다.
3. 영상 시간축 검증
   - 전체 길이 기준 막대와 시작/종료/전체 길이 정보 표시
4. 하단 2열 결과
   - 무결성 검증 결과
   - 블록체인 검증
5. CoC와 검증 항목 상세
   - Chain of Custody 요약은 분석 진행 요약과 같은 가로 타임라인 UI로 표시한다.
   - 각 단계는 체크 원 + 단계명 + 시간 + 처리자를 함께 보여준다.
   - 작은 카드 여러 개가 아니라 하나의 라인 위에 단계가 이어지는 형태로 둔다.
   - 업로드/해시 생성/분석 요청/분석 완료/보고서 생성 흐름으로 표시한다
   - 실제 CoC 로그가 있으면 로그 기반으로, 없으면 현재 증거 상세 데이터의 업로드/분석 시각 기준으로 표시한다
   - 검증 항목 상세는 프레임 누락, 프레임 반복, 프레임 혼합, 자연스러운 흐름, SHA-256 검증, 전자서명, 블록체인 검증을 표로 보여준다

## 데이터 정책

- 실제 백엔드 필드가 없는 값은 가짜로 만들지 않는다.
- `originalHash`로 임의 Tx Hash를 만들지 않는다.
- 블록체인 트랜잭션 필드가 없으면 `미제공` 또는 `등록 대기`로 표시한다.
- 프레임별 위변조 점수 데이터가 없으면 차트를 지어내지 않고 상태 UI를 표시한다.
- CoC 로그가 없을 때도 가짜 로그 ID를 만들지 않는다. 화면용 단계는 현재 API가 제공하는 시각 필드로만 구성한다.

## UI 원칙

- 폰트는 과하게 굵게 하지 않는다.
- 카드 제목은 작고 명확하게 둔다.
- 결과 값만 색으로 강조한다.
- 정상/주의/위험은 색만으로 구분하지 않고 텍스트를 함께 표시한다.
- 기존 탭 구조와 API 호출 흐름은 변경하지 않는다.

- API 호출
- mock/real 정책
- 증거 선택 로직
- 복사 callback 동작
