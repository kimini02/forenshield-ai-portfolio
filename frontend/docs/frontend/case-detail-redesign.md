# 사건 상세 페이지 디자인 정리

## 목표

분석 이력이나 업로드 완료 후 이동하는 상세 화면은 하나로 통일한다.
상세 화면은 `/cases/{caseKey}?evidenceId={evidenceId}` 한 곳만 사용하고, 사용자는 좌측 증거 목록에서 증거를 바꾸며 우측 4개 탭에서 결과를 확인한다.

## 기준 화면

레퍼런스처럼 다음 구조를 따른다.

```text
상단 공통 헤더
└─ breadcrumb: 분석이력 > 사건 상세
└─ 사건 제목 / caseId / 사건 상태 요약

본문 2컬럼
├─ 좌측 카드: 증거 파일 목록
└─ 우측 영역
   ├─ 카드 1: 선택된 증거 요약
   ├─ 탭 메뉴: 분석 요약 / 딥페이크·모델 분석 / 위변조·무결성 검증 / 메타데이터·보고서
   └─ 카드 2: 선택된 탭의 상세 콘텐츠
```

## 화면 구조

### 1. 상단 사건 헤더

- 헤더 메뉴에서는 `분석이력`이 active 상태여야 한다.
- breadcrumb는 `분석이력 > 사건 상세`로 표시한다.
- 사건명은 가장 큰 제목으로 표시한다.
- caseId는 사건명 아래에 mono 스타일로 표시한다.
- 사건 요약 칩:
  - 생성일
  - 상태
  - 총 증거 수
  - 완료
  - 처리 중
  - 실패

### 2. 좌측 증거 파일 카드

- 좌측은 하나의 카드로 고정한다.
- 카드 제목은 `증거 파일`.
- 우측 상단에 `n개` 배지를 둔다.
- 각 증거 item은 버튼으로 만든다.
- 선택된 증거는 teal border/background로 강조한다.
- 썸네일은 실제 `thumbnailUrl` 또는 `previewUrl`이 있으면 사용한다.
- 실제 썸네일이 없으면 임시 그래픽을 쓰되, 실제 영상처럼 보이는 과한 fake 이미지는 피한다.
- 각 item에 표시할 정보:
  - 파일명
  - `EVD-{evidenceId}`
  - 분석 상태
  - 파일 유형 `VIDEO`

### 3. 우측 카드 1: 선택 증거 요약

이 카드가 탭보다 위에 있어야 한다.

구성:

- 상단 배지 영역
  - 위험 등급 또는 분석 상태
  - 분석 상태
  - 확장자
- 파일명
- 파일 기본 정보
  - 증거번호
  - 업로드 일시
  - 파일 유형
  - 파일 크기
  - 해상도
  - 재생 시간
- 오른쪽 점수 카드 2개
  - 최종 위험도
  - 신뢰도
- 하단 진행 바
  - 완료/진행/실패/대기 상태를 표현한다.

주의:

- `riskScore`, `confidenceScore`가 없으면 임의 점수를 만들지 않는다.
- real 모드에서 분석 근거가 없으면 `-`, `분석 대기`, `분석 근거 없음`처럼 표시한다.
- “정상”, “원본”, “딥페이크 아님”으로 단정하지 않는다.

### 4. 탭 메뉴

탭은 반드시 선택 증거 요약 카드 아래에 둔다.

탭 목록:

1. 분석 요약
2. 딥페이크 · 모델 분석
3. 위변조 · 무결성 검증
4. 메타데이터 · 보고서

스타일:

- 전체 탭 메뉴는 하나의 가로 카드처럼 보이게 한다.
- 활성 탭은 파란색 계열 underline 또는 border로 표시한다.
- 비활성 탭은 muted 색상.
- 탭 높이는 너무 낮지 않게 유지한다.
- 탭 클릭 시 레이아웃이 움직이면 안 된다.

### 5. 우측 카드 2: 탭 상세 콘텐츠

탭 아래에는 선택된 탭의 콘텐츠 카드가 온다.

#### 분석 요약

레퍼런스처럼 4개 요약 카드 + 진행 요약으로 구성한다.

- 파일 기본정보
- 판정 요약
- 무결성 검증
- 메타데이터/보고서
- 분석 진행 요약

#### 딥페이크 · 모델 분석

- 모델 결과 카드
- 프레임별 위험도
- 의심 구간
- 탐지 근거
- 실제 결과가 없으면 `분석 근거 없음` 상태 UI

#### 위변조 · 무결성 검증

- SHA-256
- 복사 버튼
- 전자서명 상태
- CoC 타임라인
- 블록체인 앵커링 상태

#### 메타데이터 · 보고서

- 메타데이터 표
- 보고서 생성 상태
- 검증번호
- QR/검증 정보
- PDF 다운로드 버튼

## 데이터 정책

- 상세 화면은 `fetchCaseDetail(caseId)`와 `fetchEvidenceDetail(evidenceId)`만 사용한다.
- `/evidences/{id}`는 상세 화면을 직접 그리지 않고 `/cases/{caseKey}?evidenceId={id}`로 이동만 한다.
- real API 실패를 mock 데이터로 대체하지 않는다.
- `riskScore`만으로 프레임 위험도, 의심 구간, 탐지 근거를 생성하지 않는다.
- 백엔드 필드가 없으면 빈 상태 UI를 보여준다.

## 구현 순서

1. 상단 레이아웃 재정렬
   - breadcrumb
   - 사건 헤더
   - 좌측 증거 카드
   - 우측 증거 요약 카드

2. 탭 위치 수정
   - 증거 요약 카드 아래로 이동
   - 활성 탭 파란색 스타일 적용
   - 탭 높이 고정

3. 분석 요약 탭 재구성
   - 4개 요약 카드
   - 진행 타임라인
   - 과한 긴 텍스트 줄바꿈 처리

4. 딥페이크/무결성/메타데이터 탭 순차 정리
   - 기존 데이터 흐름 유지
   - UI만 정리

## 완료 기준

- 상세 진입 경로가 `/cases/{caseKey}?evidenceId={evidenceId}`로 통일되어 있다.
- 좌측 증거 목록과 우측 상세 영역이 명확히 분리되어 있다.
- 선택 증거 요약 카드가 탭보다 위에 있다.
- 탭은 파란색 active 스타일이고 클릭 시 흔들리지 않는다.
- 분석 요약 탭은 카드가 너무 난잡하게 흩어지지 않는다.
- API 호출, 상태 소유, mock/real 정책은 변경하지 않는다.
- `pnpm build`가 통과한다.
