## 5. 트러블슈팅: 분석 완료 후 사건 상세 404

### 5-1. 증상

- URL: `https://forenshield.example.com/cases/유튜브%20쇼츠6?evidenceId=59`
- 화면: **「데이터 로드 오류 — 현재 DB에서 이 사건을 찾을 수 없습니다」**
- GPU 로그: evidence 59 분석 **COMPLETED** (추론 성공)
- 브라우저 콘솔:

```text
GET /api/v1/cases?caseKey=%25EC%259C%25A0%25ED%258A%259C%25EB%25B8%258C%2520%25EC%2587%25BC%25EC%25B8%25A06
→ 404
```

(Vercel Analytics 스크립트 404는 별도 이슈, 기능과 무관)

### 5-2. 원인 분석

**핵심: `caseKey` 이중 URL 인코딩**

1. 분석 완료 후 이동 URL 생성 시 `encodeURIComponent(사건명)` → 경로에 1회 인코딩  
   예: `/cases/%EC%9C%A0%ED%8A%9C%EB%B8%8C%20%EC%87%BC%EC%B8%A06`
2. Next.js `useParams().id`가 **이미 인코딩된 문자열**을 그대로 반환하는 경우 있음  
   → `caseId` = `%EC%9C%A0%ED%8A%9C%EB%B8%8C%20%EC%87%BC%EC%B8%A06`
3. `fetchCaseDetail`에서 다시 `encodeURIComponent(caseId)` → **2중 인코딩**  
   → `%25EC%25...` (`%`가 `%25`로 또 인코딩)
4. 백엔드는 `caseKey`로 DB 조회:

```sql
-- EvidenceRepository
AND (e.caseNumber = :caseKey OR e.caseName = :caseKey)
```

- 기대값: `유튜브 쇼츠6`
- 실제 전달: `%EC%9C%A0%ED%8A%9C%EB%B8%8C%20%EC%87%BC%EC%B8%A06` (문자 그대로)
- → **CASE_NOT_FOUND (404)**

**왜 GPU는 됐는데 화면만 안 됐나**

- 분석·저장은 `evidenceId` 기준으로 정상
- 사건 상세는 **URL의 사건명(caseKey)** 으로 조회 → 인코딩 버그만 터짐
- 한글·공백 사건명에서 특히 재현

### 5-3. 해결

**커밋:** `c21e1ee` — `fix: 한글 사건명 caseKey 이중 인코딩으로 상세 404 나는 문제 수정`

#### (1) 공통 유틸 추가 — `lib/route-params.ts`

```ts
decodeRouteParam(value)      // 1~3회 decodeURIComponent로 이중 인코딩 해소
buildCaseDetailPath(caseKey, evidenceId?)  // decode 후 1회만 encode
```

#### (2) API 호출 정규화 — `lib/api/evidence-detail.ts`

```ts
const caseKey = decodeRouteParam(caseId)
const params = new URLSearchParams({ caseKey })
return apiRequest(`/api/v1/cases?${params}`)
```

#### (3) 사건 상세 페이지 — `app/cases/[id]/page.tsx`

```ts
const caseId = decodeRouteParam(Array.isArray(id) ? id[0] : id)
```

#### (4) 분석 완료 후 이동 경로 변경 — `analysis-request-flow.tsx`

사건명 URL 직행 대신 **증거 ID 경유** (인코딩 이슈 회피):

```ts
// 변경 전
router.push(`/cases/${encodeURIComponent(caseName)}?evidenceId=...`)

// 변경 후
router.push(`/evidences/${evidenceId}`)
```

`/evidences/[id]` → `fetchEvidenceDetail` → API의 `caseName`으로 `/cases/...` 리다이렉트 (`buildCaseDetailPath` 사용)

#### (5) 링크 일괄 정리

- `app/evidences/[id]/page.tsx`
- `components/recent-analyses.tsx`
- `app/main/_components/dashboard-overview.tsx`
- `app/mypage/_components/case-history-list.tsx`

### 5-4. 검증 방법 (배포 후)
