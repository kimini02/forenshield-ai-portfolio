# v2 사건 중심 증거 등록/분석 UI 플로우

## 목적

v2는 파일을 바로 분석하는 화면이 아니라, **사건을 먼저 만들고 그 사건 안에 증거 영상을 등록한 뒤, 등록된 증거에서 분석을 실행하는 구조**로 정리한다.

핵심 흐름은 다음과 같다.

```text
사건 등록 -> 증거 업로드 -> 증거 목록 관리 -> 분석하기 -> 결과 보기 -> 보고서 생성
```

업로드와 분석은 분리한다.  
영상을 업로드하면 즉시 분석하지 않고, 우선 사건에 속한 증거로만 등록한다.

## 상단 메뉴 구조

상단 메뉴는 최대한 단순하게 둔다.

```text
대시보드 | 사건 관리 | 보고서
```

### 대시보드

- 전체 사건 현황
- 위험 사건 수
- 최근 분석 현황
- 처리 상태 요약

### 사건 관리

- 사건 등록
- 사건 목록 확인
- 사건 상세 진입
- 증거 업로드
- 증거별 분석 실행
- 분석 결과 확인

### 보고서

- 생성된 보고서 목록
- 사건명, 증거 ID, 판정 결과 확인
- 보고서 보기
- 보고서 다운로드 또는 반출 준비

`비교검증`은 상단 메뉴로 분리하지 않고, 사건 상세의 `분석하기` 안에서 선택하는 분석 유형으로 둔다.

## 사건 관리 화면

`사건 관리`를 누르면 사건 목록 화면이 나온다.

### 주요 구성

- 화면 제목: `사건 관리`
- 주요 버튼: `사건 등록`
- 검색: 사건명, 사건 ID, 증거 ID 기준 검색
- 사건 목록

### 사건 목록 표시 항목

- 사건명
- 사건 ID
- 증거 수
- 분석 상태
- 최근 분석일
- 대표 증거
- 상세 보기

이 화면에서는 증거 업로드를 직접 하지 않는다.  
증거 업로드는 사건을 만든 뒤, 사건 상세 화면에서 진행한다.

## 사건 등록

`사건 등록` 버튼을 누르면 모달을 띄운다.

### 입력 항목

- 사건명
- 사건 설명 또는 메모

### 등록 후 동작

- 새 사건을 생성한다.
- 생성 직후 해당 사건 상세 화면으로 이동한다.
- 새 사건의 초기 상태는 `증거 없음` 또는 `등록 대기`로 둔다.

## 사건 상세 화면

사건 상세 화면은 탭을 많이 나누지 않고, **등록된 증거 중심 화면**으로 구성한다.

### 주요 구성

- 사건 정보 요약
- `증거 추가` 버튼
- 등록된 증거 목록
- 증거별 액션 버튼

### 증거 카드 예시

```text
증거 1 / EVD-2024062701
VIDEO · 등록 완료 · 미분석
대표 증거

[분석하기] [대표 지정] [사용 제외] [대체 증거 등록]
```

원본 파일명은 기본 목록에 노출하지 않는다.  
필요한 경우 `상세 정보`를 펼쳤을 때만 작게 표시한다.

## 증거 업로드

`증거 추가`를 누르면 파일 업로드 모달 또는 패널을 띄운다.

### 업로드 후 동작

- 즉시 분석하지 않는다.
- 사건에 증거로만 등록한다.
- 화면에는 `증거 1`, `증거 2`처럼 표시한다.
- 각 증거에는 새 EVD ID를 부여한다.
- 초기 분석 상태는 `미분석`으로 둔다.

## 분석하기

각 증거 카드의 `분석하기` 버튼을 누르면 분석 유형 선택 모달 또는 하단 패널을 띄운다.

### 분석 유형

- 딥페이크 탐지
- 위변조/무결성 검증
- 비교검증

### 딥페이크 탐지

- 현재 증거 1개를 기본 선택한다.
- 필요하면 사건 안의 다른 활성 증거를 추가 선택할 수 있다.
- `분석 시작`을 누르면 분석을 실행한다.

### 위변조/무결성 검증

- 현재 증거 1개를 기본 선택한다.
- 파일 해시, 무결성 상태, 시간축/프레임 이상 여부를 확인하는 흐름으로 둔다.
- `분석 시작`을 누르면 분석을 실행한다.

### 비교검증

- 기준 증거는 현재 선택한 증거로 둔다.
- 비교 대상 증거를 사건 안에서 선택한다.
- 기준 증거와 비교 대상 증거는 서로 달라야 한다.
- `비교검증 시작`을 누르면 분석을 실행한다.

## 분석 완료 후

분석이 끝나면 해당 증거 카드 상태를 갱신한다.

```text
미분석 -> 분석 완료
```

분석 완료된 증거에는 `결과 보기` 버튼을 표시한다.

`결과 보기`를 누르면 기존 상세 결과 화면으로 이동한다.

## 사용 제외와 대체 등록

포렌식 정책상 원본 증거는 삭제하지 않는다.

### 사용 제외

잘못 올린 증거는 삭제하지 않고 `사용 제외`로 마킹한다.

- 증거는 목록에 남긴다.
- 화면에서는 회색 처리한다.
- 분석 선택 목록에서는 제외한다.
- 제외 사유를 표시한다.

### 대체 증거 등록

잘못 올린 파일을 바꾸는 기능은 `수정`이 아니라 `대체 증거 등록`으로 처리한다.

- 기존 증거는 `대체됨` 상태가 된다.
- 새 파일은 새 EVD ID를 받는다.
- 기존 증거와 신규 증거의 관계를 표시한다.

```text
EVD-2024062701 -> EVD-2024062705
```

## 보고서 메뉴

상단 `보고서` 메뉴는 최종 산출물 목록만 담당한다.

### 보고서에서 할 일

- 생성된 보고서 목록 확인
- 사건별 보고서 확인
- 증거 ID, 판정 결과, 생성일 확인
- 보고서 보기
- 보고서 다운로드 또는 반출 준비

사건 상세 안에는 별도 `보고서` 탭을 만들지 않는다.  
분석 결과 화면 안에 `보고서 생성` 버튼만 둔다.

## 최종 사용자 흐름

```mermaid
flowchart LR
  A["사건 관리"] --> B["사건 등록"]
  B --> C["사건 상세"]
  C --> D["증거 추가"]
  D --> E["등록된 증거"]
  E --> F["분석하기"]
  F --> G["딥페이크 / 위변조 / 비교검증"]
  G --> H["결과 보기"]
  H --> I["보고서 생성"]
  I --> J["보고서"]
```

## 핵심 원칙

- 상단 메뉴는 `대시보드`, `사건 관리`, `보고서`로 단순화한다.
- `분석요청`, `분석이력`, `비교검증`은 상단 메뉴에서 제거한다.
- 사건을 먼저 등록하고, 사건 상세에서 증거를 추가한다.
- 증거 업로드와 분석 실행은 분리한다.
- 증거 목록에는 원본 파일명을 노출하지 않는다.
- 원본 증거는 삭제하지 않고 `사용 제외` 또는 `대체 증거 등록`으로 처리한다.
- 분석은 증거 카드의 `분석하기`에서 시작한다.
- 비교검증은 사건 안의 분석 유형 중 하나로 둔다.
